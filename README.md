# ELINK42 Web 0.6.18 / 设备固件 v30

v30 修复有线安装后首次开机误入空白图片日历、首次蓝牙连接才显示信息页的问题。启动时直接显示白底设备信息，放大设备名、完整蓝牙 MAC 和固件版本。Web 0.6.18 移除误收的操作报错截图，其他图片编号和图片字节保持。

沿用 v28 的 SPI、UART、Flash 可达调用链中的复位、就绪、计时和校验等待保护。外设不完成或计时器停走时退出；Flash 失败不再继续写入或把图片、启动记录报告为保存成功。保留原蓝牙底层代码、面板波形、身份与校准数据，正常路径的外设写入顺序通过与 v24 的对照检查。

相较稳定 v28，底层仅增加已精确授权的默认配置返回处 6 字节启动钩子；SPI、UART、Flash 保护代码与 v28 一致。两种屏型、无配置与四种已保存模式均执行实际首次绘图路径，首次蓝牙状态查询不再重复初始化。

本轮没有连接或刷写设备。离线验证通过不等于真实供电、屏幕和长期蓝牙稳定性已经验收。

## 升级路线

一个 ZIP，网页确认一次，最多两次写入；每次重启后核对同一设备的版本。第一步接收器保持原底层，只接受精确配对的 v30；最终 v30 安装并重启后才具备本次全部等待保护。失败停止，不自动重发。

| 当前版本 | OTA 路线 |
|---|---|
| v3–v14（含 v10/v12 诊断版） | 对应旧基线的 v29 → v30 |
| v16–v17 | 对应修复基线的 v29 → v30 |
| v19、v21、v24、v28 | 对应稳定基线的 v29 → v30 |
| v29 | 配套 v30，一次 |
| v15、v18、v20、v23、v27 | 锁定原配旧镜像，无法在两次写入内完成；本网页不发送升级命令，使用对应 HEX |
| v1、v2 | 旧启动记录检查不兼容，使用对应 HEX |
| v30 或更高 | 整合包不升级、不回退 |

OTA 会清空设备图库，请先备份。停留在 OTA 页面时暂停三分钟空闲断连，传输、校验、等待重启期间也有保护。最终重启先显示设备名、MAC 和固件版本，日历需手动启用。

v3–v8 用已验证的带序号暂停回执准备升级，不要求其尚未具备的 v9 计时标志，也不调用旧屏幕初始化。v3/v4 仍要求启动记录可核验，旧记录长度超限会在擦除前停止并保留连接；此时使用 HEX，不能由网页跳过设备检查。

## 有线安装

有线使用对应屏型的 v30 HEX，可直接安装 v30，不需要 v29。HEX 完整覆盖应用区 `0x00404000–0x0043E3C3`，共 238,532 字节；需保留现有引导、MAC、校准和身份区，不能全片擦除。它不包含空白芯片的引导程序。三色、四色不能交叉刷写。

## 日常使用

网页保留日历、图片、设备图片、更多四个入口，58 张内置缩略图及 12 个月节气壁纸。界面支持 English、简体和繁体，设备继续按现有字库能力显示中国、台湾、新加坡日历。新保存的 256×300 日历壁纸填满左侧，右侧日期由设备更新。

“一键换图”按当前模式更换左侧或全屏图片，顺延使用空位置，满了提示手动删除。多图可离线按每天、每周或每月凌晨 0 点更换。保留 v24 的日期、字体和换图逻辑，以及 Web 0.6.16 避免重复刷新、等待就绪后提交轮播设置的修复。

## 验证范围

执行真实 Thumb 代码与故障化 MMIO，覆盖正常路径、外设不就绪、运行中停钟、超时后的清理及下一次状态查询。旧版同条件能复现卡住，新版可返回。完整虚拟 OTA 执行原生签名、SHA、保护区、精确目标配对和启动记录读回，不能代替实物 OTA 或无线链路长期验收。

ROM 内部不返回、设备供电和射频环境不在这些离线测试的保证内。系统复位命令的其他等待、真实 RTC 重入的可达性，未在本次 SPI/UART/Flash 范围内改写。

公开控制台源码可用 Python 运行 `python tools/build_site.py`，Node.js 运行 `node --test tests/*.cjs`。本地整合包解压后运行 `Start.cmd`。私有签名密钥、SDK、ELF 和固件分析工作区不在公开包中。
